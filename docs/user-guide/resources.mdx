OpenTelemetry [Resources](https://opentelemetry.io/docs/specs/otel/resource/sdk/) describe the entity producing telemetry: service name, version, host, cloud provider, and other properties. NeMo Lens auto-detects a handful of environment-specific attributes to make runs filterable without manual configuration.

## Default Resource Attributes

Every exporter-rank process emits these attributes (set in `providers.py:build_providers`):

| Attribute | Source | Example |
|---|---|---|
| `service.name` | `config.service_name` (populated from `OTEL_SERVICE_NAME` through `NemoLensConfig.from_env()`, default `"nemo"`) | `"megatron-lm"` |
| `service.version` | `nemo.lens.__version__` | `"0.1.0"`, `"0.1.0.post3+gabc1234"` |
| `service.instance.id` | `"{run_id}-rank{rank}"` when `nv.dl.rank` is available through either channel and `service.instance.id` is not explicit; otherwise left to the SDK | `"abc123-rank0"` |
| `nv.dl.rank` | caller-supplied `resource_attributes` or `OTEL_RESOURCE_ATTRIBUTES` | `0` |
| `nv.dl.world_size` | caller-supplied `resource_attributes` or `OTEL_RESOURCE_ATTRIBUTES` | `8` |
| `nemo.run.id` | `config.run_id` (auto-generated if empty) | `"abc123"` |
| `nemo.user.id` | `config.user` (if set) | `"my-team"` |
| `deployment.environment` | `DEPLOYMENT_ENV` or `ENVIRONMENT` env var | `"production"` |

## Auto-Detected Resource Attributes

The `nemo.lens.resources.detect_resource()` function merges attributes from three sources:

### Local Process Attributes with `detect_local()`

| Attribute | Description |
|---|---|
| `host.name` | Hostname from `socket.gethostname()` |
| `process.pid` | Python's `os.getpid()` |
| `host.gpu.count` | GPU count from `CUDA_VISIBLE_DEVICES` or `nvidia-smi`. Best-effort; omitted entirely when undetectable (no `nvidia-smi` and `CUDA_VISIBLE_DEVICES` unset). An empty `CUDA_VISIBLE_DEVICES` reports `0`. |

### Slurm Environment Attributes with `detect_slurm()`

This helper returns attributes when `SLURM_JOB_ID` is set or when
launch-provided `OTEL_RESOURCE_ATTRIBUTES` contains a selected Slurm or run
identity value. With a local job ID, it derives Slurm resource attributes from
the local environment. Inherited values can activate detection independently
and take precedence over caller-provided `resource_attributes` defaults and
locally derived fallback values. Empty inherited values are ignored.

| Attribute | Source env var |
|---|---|
| `slurm.job.id` | `SLURM_JOB_ID` |
| `slurm.job.id.raw` | Raw `SLURM_JOB_ID` |
| `slurm.array.job_id` | `SLURM_ARRAY_JOB_ID`, or `SLURM_JOB_ID` for non-array jobs |
| `slurm.array.task_id` | `SLURM_ARRAY_TASK_ID`, or `"0"` for non-array jobs |
| `slurm.array.count` | `SLURM_ARRAY_TASK_COUNT`, or `1` when unset |
| `slurm.sluid` | `LENS_SLURM_SLUID` or `NV_LAUNCH_SLUID` |
| `slurm.array.sluid` | `LENS_SLURM_ARRAY_SLUID` or `NV_LAUNCH_ARRAY_SLUID` |
| `slurm.job.name` | `SLURM_JOB_NAME` |
| `slurm.cluster.name` | `SLURM_CLUSTER_NAME` |
| `slurm.partition` | `SLURM_JOB_PARTITION` or `SLURM_PARTITION` |
| `slurm.head_node.name` | `SLURMD_NODENAME` outside a Slurm step, or inherited from launch attributes |
| `slurm.nnodes` | `SLURM_JOB_NUM_NODES` or `SLURM_NNODES` |
| `slurm.ntasks` | `SLURM_NTASKS` |
| `slurm.restart_count` | `SLURM_RESTART_COUNT`, or `0` when unset |
| `slurm.job.user` | `SLURM_JOB_USER` |
| `slurm.job.account` | `SLURM_JOB_ACCOUNT` |
| `slurm.job.qos` | `SLURM_JOB_QOS` |
| `slurm.job.reservation` | `SLURM_JOB_RESERVATION` |
| `slurm.segment` | `SLURM_SEGMENT` |
| `slurm.topology.addr` | `SLURM_TOPOLOGY_ADDR` |
| `slurm.topology.addr_pattern` | `SLURM_TOPOLOGY_ADDR_PATTERN` |
| `nv.dl.job.uuid` | Derived from Slurm cluster and submitted job ID, or inherited from launch attributes |
| `nv.dl.run.uuid` | Inherited from launch attributes |

`detect_slurm()` returns `slurm.array.count`, `slurm.nnodes`, `slurm.ntasks`,
and `slurm.restart_count` as integers whether they are derived locally or
inherited through `OTEL_RESOURCE_ATTRIBUTES`. Other inherited values remain
strings. An empty inherited value, or a non-integer value for one of those four
attributes, is discarded so that a valid locally derived value can be used as
the fallback. If no valid local value exists, the attribute is omitted.

The table above is the complete allowlist of attributes that `detect_slurm()`
reads from `OTEL_RESOURCE_ATTRIBUTES`; every accepted key has an explicit
normalizer. Other resource attributes are ignored by this helper, but they
remain in `OTEL_RESOURCE_ATTRIBUTES` and are still read independently by the
OpenTelemetry SDK.

Retired keys such as `slurm.nodelist`, `slurm.cluster`, and
`slurm.torchelastic.restart_count` are not emitted for new telemetry.

### Kubernetes Environment Attributes with `detect_kubernetes()`

These attributes are active when `KUBERNETES_SERVICE_HOST` is set or the `/var/run/secrets/kubernetes.io` directory exists. This helper maps the following variables:

| Attribute | Source env var |
|---|---|
| `k8s.namespace.name` | `K8S_NAMESPACE` |
| `k8s.pod.name` | `K8S_POD_NAME` (falls back to `HOSTNAME`) |
| `k8s.pod.uid` | `K8S_POD_UID` |
| `k8s.node.name` | `K8S_NODE_NAME` |
| `k8s.container.name` | `K8S_CONTAINER_NAME` |
| `k8s.job.name` | `K8S_JOB_NAME` |

`HOSTNAME` is used as a fallback for `k8s.pod.name` only when `K8S_POD_NAME` is unset.

## Add Custom Resource Attributes

Pass the `resource_attributes` argument to `setup_telemetry`:

```python
handle = setup_telemetry(
    config,
    resource_attributes={
        'nv.dl.rank': rank,
        'nv.dl.world_size': world_size,
        'dl.tensor_parallel.size': 4,
        'dl.pipeline_parallel.size': 2,
        'dl.data_parallel.size': 8,
        'megatron.num_layers': 32,
        'megatron.precision': 'bf16',
    },
)
```

These attributes merge with the auto-detected set. In Jaeger, they appear as **Process** tags and are filterable across every span in the run.

<Warning>
NeMo Lens does not derive `nv.dl.rank` — it has no notion of a rank. If you omit
it, a warning is logged at startup: telemetry from this process cannot be
filtered by rank in the collector, and `service.instance.id` is not rank-derived.

The process itself stays identifiable either way — `host.name` and `process.pid`
are always attached, and `service.instance.id` is left to the SDK, which supplies
a per-process UUID from version 1.43.0 onward. What you lose is rank-based
filtering and correlation, not the ability to tell two processes apart.

NeMo Lens deliberately does **not** read `RANK` or `WORLD_SIZE` to fill the gap —
that would restore the rank-awareness it was designed to shed, and would be wrong
for any caller whose rank is not the process's global rank.

The warning is suppressed (dropped to `DEBUG`) when you supply your own
`service.instance.id`, through either channel. A launcher agent or sidecar that
names itself and has no training rank to claim is a correct configuration, not
one to nag about once per node per job. A genuinely single-process caller can
also pass rank `0`.
</Warning>

Pass the `resource_attributes` argument to `setup_telemetry`:

```python
handle = setup_telemetry(
    config,
    resource_attributes={
        'nv.dl.rank': rank,
        'nv.dl.world_size': world_size,
        'dl.tensor_parallel.size': 4,
        'dl.pipeline_parallel.size': 2,
        'dl.data_parallel.size': 8,
        'megatron.num_layers': 32,
        'megatron.precision': 'bf16',
    },
)
```

These attributes merge with the auto-detected set. In Jaeger, they appear as **Process** tags and are filterable across every span in the run.

## Two Channels for Supplying Attributes

Resource attributes reach NeMo Lens two ways, and both are first-class:

| Channel | Use when |
|---|---|
| `resource_attributes=` on `setup_telemetry` | You control the call site. |
| `OTEL_RESOURCE_ATTRIBUTES` in the process env | You do not — a spawned worker, an `exec`'d relaunch, a launcher-started agent. |

The env var is the standard OTel channel (`key=value,key=value`, percent-encoded)
and is the **only one that survives a `spawn` or `exec`**, so it is how a child
process supplies its own `nv.dl.rank` when it has no `setup_telemetry` call site to
reach. NeMo Lens resolves both before deriving anything from them, so an
env-supplied rank produces the same `service.instance.id` a caller-supplied one
would.

On conflict the caller's dict wins, matching what the OTel SDK does with the same
inputs.

<Note>
The two channels produce different **types** for the same attribute:
`resource_attributes={NV_DL_RANK: 3}` yields the integer `3`, while
`OTEL_RESOURCE_ATTRIBUTES="nv.dl.rank=3"` yields the string `"3"` — the env
channel is string-only by construction. A collector or backend filtering on a
numeric attribute should tolerate both. NeMo Lens does not generally coerce env
attributes; the four numeric Slurm attributes normalized by `detect_slurm()` are
the exception described above. See `semconv.py`.
</Note>

```bash
# parent, before spawning the child
export OTEL_RESOURCE_ATTRIBUTES="nv.dl.rank=5,nv.dl.world_size=8,nemo.run.id=abc123"
```

<Note>
Hand-rolling that string is easy to get subtly wrong — values need
percent-encoding, keys must **not** be encoded, and an inherited value has to be
merged without piling up duplicate keys. Use the helpers described in
[Propagate Attributes to a Child Process](#propagate-attributes-to-a-child-process)
instead of building it yourself.
</Note>

## Propagate Attributes to a Child Process

A process that cannot reach a `setup_telemetry` call site — a spawned checkpoint
worker, an `exec`'d relaunch, a launcher-started agent — receives its resource
attributes through `OTEL_RESOURCE_ATTRIBUTES`. That is the only channel that
survives the boundary: `multiprocessing.Process` has no `env` parameter at all,
so mutating `os.environ` before `start()` is not one option among several.
When both channels provide the same key, the caller's `resource_attributes`
mapping wins, matching the OpenTelemetry SDK.

Use the helpers in `nemo.lens.resources.attributes` rather than formatting the
value by hand:

```python
import os
import subprocess

from nemo.lens.resources import (
    extend_otel_resource_attributes,
    publish_otel_resource_attributes,
)
from nemo.lens.semconv import NV_DL_RANK, NV_DL_WORLD_SIZE

# multiprocessing — publish while the child starts, then restore the environment
with publish_otel_resource_attributes(
    {NV_DL_RANK: rank, NV_DL_WORLD_SIZE: world_size},
    overwrite=True,
):
    ctx.Process(target=worker).start()

# subprocess — build the child's environment
value = extend_otel_resource_attributes(
    os.environ.get('OTEL_RESOURCE_ATTRIBUTES'),
    {NV_DL_RANK: rank, NV_DL_WORLD_SIZE: world_size},
    overwrite=True,
)
env = {**os.environ, 'OTEL_RESOURCE_ATTRIBUTES': value}
subprocess.Popen(cmd, env=env)
```

Use `overwrite=True` when current child identity must replace stale inherited
values. Use `overwrite=False` for additive launcher and Slurm behavior, where an
existing value is authoritative. `extend_otel_resource_attributes()` is pure;
`set_otel_resource_attributes()` updates an environment mapping permanently;
`publish_otel_resource_attributes()` updates it only for the context lifetime.
Publisher contexts may nest within one thread, but they must not overlap across
threads because environment variables are process-global. Serialize publication
when multiple threads can launch children.

### What It Handles

| Concern | Behavior |
|---|---|
| Separators in values | Percent-encoded. Unencoded, a comma truncates its value *and* invents a key — a run id of `exp/2026-01,seed=7` arrives as `nemo.run.id="exp/2026-01"` plus a spurious `seed="7"`, with no error. |
| Value types | `str`, `bool`, `int` and `float` are stringified. During a merge, `None` and `""` mean absent and do not replace an inherited value, even with `overwrite=True`. Other values — `bytes`, a list, a dict — are dropped with a warning, because this channel is string-typed and a repr is not a round trip. |
| An inherited value | Unchanged segments are carried through byte-for-byte, never re-encoded, so a launcher's bytes survive untouched. `overwrite` explicitly selects whether inherited or added values win for duplicate keys. |
| Repeated calls | Replacing a key removes its inherited occurrence before appending the current value, so repeated publication does not accumulate stale copies. |
| Non-string keys | Dropped with a warning. `str(key)` would ship `None` as the literal attribute name `"None"`. |
| Separators in *keys* | Dropped with a warning. The SDK unquotes only the value half, so such a key has no representation; encoding it would ship the escape sequence as the attribute name. No semconv name contains `,` or `=`. |

<Note>
Values arrive in the child as **strings** — the env format has no other type.
`resource_attributes={NV_DL_RANK: 3}` yields the integer `3`, the env channel
yields `"3"`. A collector filtering on a numeric attribute should tolerate both.
NeMo Lens does not generally coerce environment attributes; the four numeric
Slurm attributes normalized by `detect_slurm()` are the exception described
above.
</Note>

For selected Slurm and run identity keys, launch-provided
`OTEL_RESOURCE_ATTRIBUTES` values are authoritative. Treat `resource_attributes`
as consumer defaults for those keys.

## Use Cases

### Filter by Global Rank

In Jaeger, use: `nv.dl.rank=0`

### Compare Distinct Runs

In Grafana, configure `nemo.run.id` as a dashboard variable, list all values, and then select the specific runs to compare.

### Filter by Parallelism Configuration

In Jaeger, use: `dl.tensor_parallel.size=4 AND dl.pipeline_parallel.size=2`

Because these are resource attributes instead of span attributes, they apply to every span without cluttering the span view.

## Attribute Conventions

- **Use standard names.** Apply standard OTel attribute names where they exist, such as `service.*`, `k8s.*`, and `host.*`.
- **Use distributed learning prefixes.** Apply the `nv.dl.*` prefix for participant resource attributes and the `dl.*` prefix for other training-specific attributes that are shared across consumers.
- **Use project-specific prefixes.** Apply the `&lt;project&gt;.*` prefix for project-specific attributes, such as `megatron.*`, `rl.*`, and `gym.*`.

See [semconv](../design/semconv.mdx) for the full attribute namespace conventions.

## Resource Detection Order

The `detect_resource()` function merges resource attributes in the following order: local, Slurm, and then Kubernetes. If a key collision occurs, the attribute from the later source takes precedence. In practice, collisions are rare because each layer uses its own namespace.

## Run Telemetry Locally

On a development machine with no Slurm or Kubernetes environment, only the `detect_local()` helper executes. Run identifiers are automatically generated as UUID values, so you can still filter by `nemo.run.id` to isolate a single local run.
